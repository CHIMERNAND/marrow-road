# Marrow Road: Design & Plan

First-person zombie siege defense. You hold a huge fortress wall at night while a horde comes up the valley, and you split your attention between your own weapon and the turrets you build on the wall.

## Where the project stands

There are two separate codebases, and neither one is the game yet.

| What | Where | State |
|---|---|---|
| Web prototypes (React + Babylon.js, generated by Grok Build) | GitHub `CHIMERNAND/marrow-road`, `main` | Three overlapping prototypes, about 15k lines: the original 2D graveyard TD (`src/game`), a first Helms Deep version (`src/helmsdeep`) and a Babylon first-person rebuild (`src/babylon`, which is what the site loads). Every model is procedural primitives, and the recent commits are feature piles (bullet-time, decapitations, ragdolls, night-sight runes, elven archers). |
| Unity 6 project (6000.3.26f1, URP) | G15 only: `D:\Dev\marrow-road\HelmsDeep`. **Not committed.** | 26 C# scripts ported from the web balance numbers. A runtime bootstrap builds the whole world from cubes in code, so there is no authored scene. It has a Windows build, an autopilot smoke test and an MP4 recorder. |

The 8 Nov captures from the Unity build show what "it looks like crap" means in practice. You see a dark blue void, box walls, a crossbow made of a few brown planks, no visible zombies and no sense of scale. The HUD and systems are ahead of the world they sit in.

Root causes:
1. **No design target.** "Enhance" prompts make an AI add features. Nothing ever defined the core loop or what done looks like.
2. **No art pipeline.** Everything is code-generated primitives, so no number of prompts will make it look good.
3. **No authored level.** Scale (the Helm's Deep point) is a level-design problem. You solve it in a scene editor with real reference dimensions, not in code constants.
4. **Too many engines.** Three web versions plus Unity split the effort.

## Decisions (proposed)

- **Engine: Unity 6 URP.** The project already exists, you have Unity experience from Glassline, and URP runs well on the RTX 3060. Unreal would look better out of the box but means starting over. Revisit only if Project Carthage ends up committing you to Unreal.
- **Freeze the web version.** Move `src/`, `public/` and `docs/` to an `archive/web-prototype` branch, so `main` holds the Unity game.
- **Art direction: realistic** (decided 2026-11-09). The look is a photoreal night siege in rain and torchlight, built on URP tuned for an RTX 3060 laptop.
- **Asset budget: $0** (decided 2026-11-09). Free sources come first (Fab free and Megascans starter, Poly Haven, ambientCG, Mixamo), and the gaps are filled by a local generation pipeline. See [`ASSET_PIPELINE.md`](ASSET_PIPELINE.md).
- **Multiplayer: solo first, co-op later** (decided 2026-11-09). We won't build networking yet, but from M2 the code follows the co-op-ready rules below so we don't have to rewrite it later.
- **Feature freeze.** Bullet-time, decapitation, ragdolls, night-sight, elven archers, the Siege Warlord and powder-cask chains go to the backlog until the core loop has been playtested and is fun.

## Core game (design target)

- **Fantasy:** You're one defender on a 15 m wall at night, in rain and torchlight, with hundreds of dead climbing the causeway.
- **Loop:** Prep phase, where you spend gold on turret sockets and upgrades. Then the wave, where you fight in first person while the turrets work. Kills give gold, the next wave is harder, and if the gate or the wall is breached you fall back or lose.
- **Player:** A heavy crossbow (charge, reload, 2–3 bolt types) and a melee weapon for zombies that reach the wall top. You move along the wall walk, the gatehouse and the towers.
- **Turrets (4):** Wall crossbow (fast, single target), boiling pitch (gate area of effect), catapult (long-range splash), ballista (pierces armor). Each has 2 upgrade tiers.
- **Enemies (5):** Shambler, runner, brute (armored), climber (ladders/wall pile-up) and battering-ram crew (gate threat).
- **Pressure points:** The main gate, two ladder zones and the culvert. Each wave pushes a different mix, so you have to move around.
- **Session:** 10 waves per night, about 20–30 minutes, with Easy / Normal / Hard.

## Scale reference (Helm's Deep)

Block out the level in ProBuilder at these dimensions before any art goes in:
- Deeping Wall about 18–22 m tall and roughly 300 m long, with a 4 m wall walk
- Causeway ramp to the gate about 60 m long and 8 m wide
- Gatehouse and keep rising above the wall, with the valley floor opening 200 m+ out toward the spawn
- Player eye height 1.7 m, so the drop to the ground has to feel dizzying

Acceptance test: put a 1.8 m human dummy at the base of the wall in a screenshot taken from the wall walk. If it doesn't look small, the scale is wrong.

## Working method (keeping cost down)

- **One milestone = one batch prompt** with a written spec and acceptance criteria, not "enhance".
- **Visual acceptance is your call.** The AI provides captures, and you approve or reject them against the milestone checklist.
- **Feedback template** instead of "it looks like crap": what you saw, what you expected, priority (blocker/major/minor), screenshot.
- Keep the existing `AutopilotSmoke.ps1` and recorder, because they let agents verify builds without you sitting at the machine.

## Co-op-ready rules (from M2)

- Game state (gold, gate HP, waves, turrets) lives in one authoritative `SiegeState` service. The player, HUD and turrets read from it and send it commands. Nothing outside it mutates state directly.
- Player input goes through an input/command layer, so a second, remote player is just another command source.
- No `static Instance` singletons for per-player things (camera, viewmodel, HUD). Global singletons are only for true globals (audio, wave director).
- Enemy simulation runs on the server's side of that boundary. Visuals subscribe to events.
- Target for co-op (post-M5): Unity Netcode for GameObjects, 2–4 players, host-authoritative.
